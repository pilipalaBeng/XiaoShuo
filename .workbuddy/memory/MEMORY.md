## 全库通病（写作组 prompt 应内置为硬约束）
1. 作者替读者总结心理（"他想怪自己""他大概在想要不要跑"）
2. 段末金句收束（"这一课，他记着""这规矩，她立"）
3. 同一句段内复读
4. **「没说出口 / 记在心里 / 这件事他记下了 / 这一课他记着」同构套式**——替人物盖章"此处应有触动"，全库出现频率最高（荒岛求生 ep03/07/08/10/13/17/20/24/25/29/30 均有）。→ 一律换具体动作或物证
5. **作者代述推理**——整段替读者把推理走完（"这电话不是用来叫救援的……秦岸不信"）。→ 只陈述可观察事实，让读者自己推
6. **每集正文头部带创作层元信息块**（本集规则清单 / 涉及人物 / 伏笔 V 编号）—— 这是规范 E1 要求的流程资产，**对外展示前必须剥离**

> 判据与对照样本见 `荒岛求生/验收存档/精修记录-ep01-24.md`（2026-09-28）。删病灶后掉字，一律用**同人设、同知识密度的具象细节**回补，不靠加水；判据是"读者能拿这段细节自己在脑子里做一次"。

## 对外发布流程（已固化）
- 脚本：`模板库/工具脚本/strip_meta.py`（剥 `>` 元信息块与 `---`，标题转「第 N 章」，`--merge` 出合本；原稿不动，输出到 `<书目>/对外版/`）。
- 用法：`python strip_meta.py "D:/Project/XiaoShuo/<书目>" --merge --book "<书名>"`
- 正文内不应有 V/R 编号（B1 门禁已保证）；剥离只处理头部。
- 荒岛求生已产出：`对外版/` 36 个单章 + 第一幕合本（30 章 6.8 万字，完整单元，给人看用这本）。

## 成本底盘

- 单集全流程 ≈ 8–9 万 tokens；精简上下文包后可压到 5–6 万
