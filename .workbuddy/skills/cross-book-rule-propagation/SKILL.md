# 跨书批量规则落地流水线

## 适用场景

把一份规则从"模板库母版"落到 N 本独立小说项目，并**焊进每本书的强制引用链**。
核心教训：**规则文件存在 ≠ 规则生效**。必须让 AI 在任何入口（宪法/AGENTS/验收/审核）都绕不开它。

## 项目背景（D:/Project/XiaoShuo）

- 17 本独立小说，每本 = 独立目录 + 独立 git + 独立 AGENTS.md
- 母版库：`D:/Project/模板库/小说工作流模板/`（独立 git 仓库）
- 每本书的核心引用文件（4 个焊点）：
  1. `宪法-<书名>.md` —— 设定权威，必须引用规则 + 人物档案
  2. `AGENTS.md` —— 项目入口，读取顺序必须把规则排前
  3. `04-每集验收清单.md` —— 质量关卡，必过项
  4. `审核Agent职责-<书名>.md` —— 独立审核，硬检查项

## 四步流程

### 第 1 步：母版沉淀（模板库）
1. 在 `D:/Project/模板库/小说工作流模板/` 新建/更新规则文件（用 `{{书名}}`/`{{幕名}}` 占位符）
2. 同步更新受影响的模板：AGENTS / 07-工作流总纲 / 04-验收清单 / 审核Agent职责 / 宪法 / README
3. git 提交（版本号 +1，如 v1.3 → v1.4）

### 第 2 步：全库播种（去占位符 → 复制到每本书）
- **关键**：母版带 `{{书名}}` 占位符，**不能直接复制**，先泛化：
  ```python
  gen = tpl.replace("{{书名}}", "<书名>")  # 或彻底去掉占位符
  ```
- 播种到每本书根目录（如 `小说写作通用规则.md`）
- **陷阱**：`os.listdir` 会包含 `.git`/`.workbuddy` 等隐藏目录 → 必须过滤 `d.startswith(".")`，且**不要**在 `.git` 里写文件

### 第 3 步：引用链焊接（4 个焊点，缺一即失效）
用 Python 脚本 + **内容锚点替换**（不用行号，各书措辞有差）：

| 焊点 | 锚点 | 注入内容 |
|---|---|---|
| 宪法 §5 人物卡后 | `### 6.` 前 | 「📍 人物连续性指引」块 |
| 宪法第二部分 | `### 1. 禁用清单` 整块 | 「铁律摘要 + 指路规则文件」 |
| 宪法修订记录前 | `## 修订记录` 前 | 「## 使用说明」块 |
| AGENTS 文件总表 | `01-动态状态库` 行后 | 新增规则文件行 |
| AGENTS 读取顺序 | `3. 01-动态状态库` 后 | `0. 规则文件` / `3.5 人物档案` |
| 验收清单 §三 | `术语表` 行后 | 新增必过项 |
| 审核职责 §二 | `## 二、N项硬检查` | 升级项数 + 插入新检查项 + **重排序号** |

**批量前必须打样 1 本**，确认无误再批量。

### 第 4 步：全库核验（逐格打勾）
用 shell 循环对每本书的每个焊点 `grep -q` 检查，输出核验表，统计「全绿/异常」。
**必须逐本核验**——本轮就发现萌宠因文件版本较老被四处漏焊。

```
⚠ 常见漏焊原因：某本书的 AGENTS/宪法是"早期简版"（无使用说明段、结构不同）
```

## 关键技术陷阱（血泪）

1. **`re.sub` 的 `\1` 后紧接数字** → `\11.5` 被解析为组引用 11 报错 `invalid group reference`。
   **解法**：改用 lambda 函数替换：`re.sub(pat, lambda m: m.group(1) + "1.5 ...", s)`
2. **中文字符串 `replace` 未匹配** → 各书可能有"标准版"与"早期简版"两种措辞。
   **解法**：先用正则提取实际文本核对，再决定用精确替换还是正则替换。
3. **序号错乱** → 插入新列表项后原序号未顺延。
   **解法**：插入后用循环重排：`idx=0; 遇 ^\d+\. 则 idx+=1 并改写`
4. **文件未落盘就被中断** → 脚本报错前已完成内存修改但未 write，下次运行需先检查状态再决定是否重跑（脚本用 `s != orig` 判断才写，天然幂等）。
5. **批量误伤隐藏目录** → 过滤 `startswith(".")`。

## 海量创作任务用并发子代理

当规则内容需要"逐本创作"（如给每本写人物档案），用 `Agent` 工具并发：
- 4 组 × 4 本，每组 prompt 完全自包含（含：要处理的书单、产出路径、参考模板路径、参考范本路径、素材读取清单、质量要求）
- 明确要求「内容必须真实来自素材，禁编造」「无占位符残留」「逐集回溯」
- 每组完成后回报：文件路径 + 主要人物数 + 轨迹锚点数

2. 模板库 git 提交
3. 追加项目记忆 `D:/Project/XiaoShuo/.workbuddy/memory/YYYY-MM-DD.md`
