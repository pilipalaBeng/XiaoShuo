# 《灵魂互换》工作流总纲（模板）

> 目标：创作、验收、进度管理交给 AI 托管运行，用户只做"决策门"确认。
> 本文件是总开关和恢复入口——新对话先读本文件即可恢复全部上下文。
> 【参数区】书名、题材、单集字数、集数规模按书填写；【固定区】决策门与防漂移规则勿改。

---

## 二、每集生产流水线

```
触发：用户说"写下一集/继续"
  ↓
1. 读：宪法 + 状态库 + 进度清单 + 伏笔活表 +（本幕生效期间）幕级大纲
  ↓
2. 定：本集素材与目标（对照幕级大纲的排期）
  ↓
3. 写：epNN-集名.md 正文（【参数区】单集字数：2000-3000 默认，按平台调整）
  ↓
4. 验：跑 04-验收清单（不通过 → 修改重验，强制，不许跳过）
  ↓
5. 更：状态库（含精确时刻锚点）
  ↓
6. 更：伏笔活表 → 进度清单 → 验收结论存入 验收存档/epNN-验收.md
  ↓
7. git commit（一集一提交，正文+状态文件同笔）
  ↓
8. 交：交付正文 + 验收结论 → 等用户决策门 → 通过后进下一集
```

## 三、决策门（【固定区】勿改）

| 门 | 时机 | 说明 |
|---|---|---|
| D1 每集确认 | 每集交付后 | 未确认不写下一集 |
| D2 剧情关键调整 | 新设定/反转方向/加删人物/改结局 | 先登记宪法《修订记录》→ 更新宪法 → 再续写；禁止无痕修改 |
| D3 发布相关 | 平台/书名/简介/封面/发布动作 | 发布行为必须用户手动 |

## 四、托管边界（【固定区】）

- AI 全自动：正文、状态/进度更新、验收、素材积累、竞品拆解、书名简介草稿。
- 必须用户做：平台账号、点击发布、签约、付费、读者互动回复（可代拟）。
- 不做：代替登录平台发布；未经确认擅自改既定剧情方向。

## 五、恢复协议

1. 新对话说"继续《灵魂互换》"或"写下一集"。
2. AI 自动读本文件 → 宪法 + 状态库 + 进度 + 伏笔活表（+ 幕大纲）→ 从流水线第 2 步继续。
3. 状态库/进度缺失某集记录 → 先向用户确认，不臆测。

## 六、外部技能接入边界（【固定区】原则）

1. 项目文件永远优先于任何外部技能；外部技能只做补强，不托管流程。
2. 产出必须再过验收 + 审核，不直接定稿。
3. 与项目文风基准/设定冲突时，以项目文件为准。
4. 每接入一个技能：登记进本表 + AGENTS.md，写明边界；**登记前确认技能真实存在**。

## 七、长篇防漂移规则（【固定区】核心）

1. **分层记忆**：长期不变 → 宪法（只改不删，修订留痕）；中期 → 幕级大纲；短期活跃 → 状态库；ep15-20 起状态库拆"活跃区 + 冷档案区"。
2. **伏笔唯一实况源**：伏笔活表管实况，宪法伏笔总表只管计划；两处不一致 = 验收打回。
3. **宪法修订留痕**：任何设定改动先登记《修订记录》再改正文。
4. **幕末大审计**：每幕结束跑一次全书一致性审计，结果写入进度清单。
5. **文件登记原则**：见第一节末。
6. **读取策略**：续写前必读活跃文件，冷档案按需检索；禁止凭印象续写。
7. **每 5 集检查点**：第 5/10/15…集验收时附加检查幕目标推进与伏笔排期执行。
