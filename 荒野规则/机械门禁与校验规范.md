# 《XiaoShuo 书库》机械门禁与校验规范（跨书契约 v1.0）

> 定位：本文件是**"什么情况机器说不行"的唯一权威**——把可机械判定的质量项从"人工勾选"里拿出来，交给脚本判定。
> 权威关系：平台红线/价值观 → 《小说写作通用规则.md》 → **本规范（机械判定）** → 各书宪法（设定） → 各书文风基准（声音） → 外部技能。
> 生效范围：书库内 17 本书 + 模板库。新增书由《批量建档.py》自动带出。
> 与其他文件的分工（勿混淆）：
> - 《小说写作通用规则.md》＝**所有书都必须遵守的铁律**（写给人看，含内容项）
> - **本规范**＝**其中"机器能判"的那部分如何判、判多严、判完怎么记账**
> - 《04-每集验收清单.md》＝每集五步验收的执行模板（内容项仍在此人工/审核判定）
> - 《文风执行细则-去AI味与标点规范.md》＝AI 痕迹的清除清单（与本规范同源，本规范负责执行）

## 一、为什么需要这份文件（事故背景，2026-09-23）

首轮全库机械巡检（650 集 / 132.5 万字）实测：

| 现象 | 实测数据 |
|---|---|
| 标点体例三套并存 | 同一份 MD5 完全一致的"跨书契约"下：11 本用「」、3 本用中文弯引号、3 本含 ASCII 直引号 |
| 引号崩坏 | 《荒野规则》16,512 个 ASCII 引号字符，其中 **5,637 处连排**，覆盖 39/85 集 |
| 逐字节复制 | 《百合》曾出现 **24 集正文同哈希**（ep60、ep62–ep84），且已被逐集标注"已验收·无 AI 味" |
| 集内复读 | 《萌宝》ep59 **重复覆盖率 99.26%**；ep50 同一段落逐字重复 6 次 |
| 元信息入正文 | 正文出现 `ep02`、`V10回收`、`第一段「出发」收束`、`5集检查点` 等创作层标记 |
| 验收失真 | 《末世异能》ep12 验收存档写"凑字重复彻底清理"，实测该集"掌心发烫"9 次 |

**共同点：以上每一条都是机械可检的。** 它们没被拦住，不是因为难检，而是因为旧验收清单把它们列为"建议项"，由人来勾——于是逐集签出"达标"。

**本规范的作用：把机械项交还给机器，把人的时间留给内容判断。**

## 二之二、校准与实现过程中修正的解析缺陷（留档）

门禁上线首日，因各书体例不统一，解析层暴露并修复了以下缺陷——留档以免回退：

| # | 缺陷 | 影响 | 修法 |
|---|---|---|---|
| 1 | `ep\d+` 黑名单用了 `(?<![A-Za-z\u4e00-\u9fa5])`，把汉字也排除了 | **系统性漏检**：中文里集号几乎总是紧贴汉字（"你顺着ep26暗线摸"） | lookbehind 只排除英文字母 |
| 2 | 伏笔编号单元格只认 `V9`，不认 `V9（新）` | 误报"活表未登记" | 允许编号后缀 |
| 3 | 台账行只认 `\| ep33 \|`，不认 `\| 01 \|` | 《荒野规则》90 集被误判为"台账 0 行" | 按表头定位集数表，两种写法都认 |
| 4 | 文首元信息块只认 `# 标题 + > 引用行 + ---` | 四种头写法（HTML 注释／YAML／无分隔符／有分隔符）中三种被判为"元信息入正文" | 四种全识别，且仅当块内含元信息关键词才算头部 |
| 5 | 引号配平按行统计 | 跨行规则条文（`「一、…` 换行 `…」`）被误判为单边引号 | 改为跨行深度扫描 |
| 6 | 字数区间只认 `-` | en dash `–`（多数书的写法）识别不到，回落到默认区间 | 支持 `- – — − ~ ～ 至` |
| 7 | 字数恰好卡边界时翻来覆去 | 3 字之差翻转结论 | 给 ±max(20, 1%) 容差 |
| 8 | 头部块未吸收其后的 `---` 分隔符 | 重建文件时 `---` 与上一行粘连（曾影响 6 个文件，已修复） | 分割器把分隔符并入头部 |

## 三、工具与用法

三个文件都在 `模板库\工具脚本\`，只用 Python 标准库（实测 Python 3.12），可复制到任意书目录运行。

| 文件 | 职责 |
|---|---|
| `novel_lint_core.py` | 共享核心库：文本切分、度量、台账解析、阈值常量。**改阈值只改这里** |
| `lint_episode.py` | **单集门禁**：一集一判，输出可粘贴的判定块 |
| `audit_library.py` | **全库巡检**：一次跑完 17 本，产出 `_总控\02-机械巡检报告.md` |

```bash
# 单集门禁（交付前必跑）——两种等价写法
python 模板库\工具脚本\lint_episode.py 僵尸 42        # 从书库根运行（书目录名 + 集数）
python ..\模板库\工具脚本\lint_episode.py . 42         # 在书目录内运行（. = 当前书）
python ..\模板库\工具脚本\lint_episode.py . 42 --json  # 机器可读
python ..\模板库\工具脚本\lint_episode.py . --all      # 全书逐集体检
python ..\模板库\工具脚本\lint_episode.py . 42 --min 1500 --max 2000   # 覆盖宪法字数区间

# 全库巡检（每周 / 每幕末 / 大改动后）
python 模板库\工具脚本\audit_library.py --root D:\Project\XiaoShuo
```

**退出码语义**（脚本可被流水线直接调用）：
- `0` ＝ 无 FAIL，机械项通过
- `1` ＝ 存在 FAIL，**打回**
- `2` ＝ 用法错误或正文/台账文件缺失

> 注意：`lint_episode.py` 的 PASS **不等于**该集可发布。它只保证"机械项干净"；内容项（节奏/逻辑/一致性/红线）仍须走《04-每集验收清单》与独立审核。

## 四、校验项与阈值（机器判定）

| 编号 | 校验项 | FAIL 条件 | WARN 条件 | 依据 |
|---|---|---|---|---|
| A1 | 引号体例 | 出现 ASCII `"` 或直角「」；或引号单边（行内引号数为奇数） | 整集无对话引号（需确认是否真无对白） | 通用规则 §一 A1/A8 + D2-01 |
| A2 | 破折号 | 单集 > 5 处 | > 3 处 | 通用规则 §一 A3 |
| A3 | 省略号/半角 | 出现 `...`（三点）或"汉字+半角 `,;:!?`" | — | 通用规则 §一 A5/A8 |
| B1 | 元信息入正文 | 正文命中：`epNN`、`VN`、`第X幕`、`检查点`、`幕末`、`待写/下一集/下一步：` | 命中：`伏笔`、`收束`、`埋线` | 长篇防漂移：创作层标记不得进产物 |
| B2 | 编号入对话 | 对话引号内出现 `R/V/D+数字`（角色不应说出内部编号） | — | 同上 |
| C1 | 集内重复覆盖率 | > 6.0% | > 2.5% | 见下方校准依据 |
| C2 | 单句复读 | 同一句（去标点后 ≥8 字）出现 ≥3 次 | — | 同上 |
| C3 | 跨集重复率 | 与最近 30 集中任一集的内容重合 > 12.0% | > 8.0% | 同上 |
| D1 | 字数 | 去空白字符数超出区间（默认 2000–3000，`--min/--max` 可覆盖） | — | 各书宪法 + D2-02 |
| D2 | 进度清单登记 | `00-进度清单.md` 无该集行 | 清单声称字数与本集两种口径均差 > 8% | 台账一致性 |
| D3 | 伏笔编号 | 正文/文首引用了活表未登记的 `VN` | 未找到活表 | 活表＝伏笔唯一实况源 |
| E1 | 文首元信息块 | 缺"涉及人物"或"本集规则/涉及规则" | — | 通用规则 §七 + 审核接口 |

### 阈值校准依据（2026-09-23 全库 650 集实测）

`C1 集内重复覆盖率`口径：**落在重复片段（8-gram 出现 ≥4 次）内的内容字符数量 ÷ 总内容字符数**，基于**去标点**文本计算——去标点是为了不把对白标签（如 `。」温知夏说，「`）误判为注水。

| 分布 | 集内重复 | 跨集重复 |
|---|---|---|
| 中位 | 0.00% | 1.08% |
| p90 | 1.11% | 6.83% |
| p95 | 5.57% | 9.43% |
| 健康书 max | ≤ 0.5%（荒岛求生、年代文、打脸虐渣、大女主、AI丧尸、僵尸） | ≤ 4.6% |
| 退化集 | 6%~99%（萌宝 ep59 达 99.26%） | 12%~43% |

取 **FAIL 6% / WARN 2.5%**（集内）与 **FAIL 12% / WARN 8%**（跨集）：落在健康分布之外，且实测能稳定抓住全部已知退化集，宁松不误杀。

> 阈值调整流程：改 `novel_lint_core.py` 的 `TH` → 重跑 `_calib` 式校准 → 在本节记录新分布与理由 → 全库重跑巡检。

## 五、在每集流水线中的位置（不可绕过）

```
1. 读基准（宪法/状态库/人物档案/进度/伏笔活表/本幕大纲）
2. 写正文 epNN-*.md
3. 【机械门禁】python lint_episode.py . NN
       ├─ 有 FAIL → 打回修改，重跑（不计入"内容打回"轮次）
       └─ 无 FAIL → 进入第 4 步
4. 内容验收（04-每集验收清单 一~五项）+ 独立审核
5. 更新 01-状态库 / 02-人物档案 / 伏笔活表 / 00-进度清单
6. 写 验收存档/epNN-验收.md：验收结论 + **脚本原始输出整段粘贴** + 打回闭环台账（见 §六）
7. git commit（一集一提交）
```

**禁止事项（命中即视为验收无效）：**
1. 手工勾选 A1/A2 而不运行脚本；
2. 脚本存在 FAIL 却写"达标/通过"；
3. 无脚本证据却写"已去重/已清理/无 AI 味/已修复"；
4. 用"字数差 3 字"之类理由打回，却不检查重复与体例；
5. 连续批量生成超过 **3 集** 而不做 D1 抽检（D1 决策门见各书《07-工作流总纲》）。

## 六、打回闭环台账（新增强制要求）

过去的教训：审核提了问题、进度清单标了"已验收"、**正文却没改**（如某集阻塞级人数错误至今未落地）；也有验收存档写"已彻底清理"而原文未动。根因是没有闭环记录。

**自本规范生效起，每集验收存档末尾必须附下表：**

| 问题编号 | 来源 | 问题摘要 | 阻塞级 | 是否已落盘 | 落盘证据 | 复审人/日期 |
|---|---|---|---|---|---|---|
| P1 | 脚本 A1 | 引号体例为 ASCII | 是 | 是/否 | 重跑 lint 输出 | |
| P2 | 审核报告 epNN | | 是/否 | | | |

规则：
1. **阻塞级（脚本 FAIL 或审核标"阻塞"）未落盘 = 该集未闭环**，不得写"达标"，不得进入下一集；
2. "落盘证据"必须是可复核的东西：重跑脚本的输出、正文行号、git commit hash；
3. 每幕末全书大审计时，逐本核对本表未闭环项。

## 七、体例迁移条款（一次性任务）

1. **迁移前**：A1 对采用「」或 ASCII 的书**全域 FAIL**，这是已知状态，属"全库统一切换事项"，**不得逐集手工改**（逐集手改会再次造成体例分裂）。
2. **迁移方式**：单独写迁移脚本，按书批量把「」与 ASCII 对引号转为 `“ ”`；脚本须处理单边/嵌套/文首元信息块，转换后逐集重跑 `lint_episode.py` 验证。
3. **迁移验收**：`audit_library.py` 报告中"引号违规集"归零，方可视为完成。
4. **迁移后**：任何新集 A1 必须 PASS；再出现 ASCII 或「」即打回。

## 八、已知盲区（诚实声明）

本规范只能提高下限，**不能当质量保证**：

1. **检索盲区**：根目录 `.gitignore` 排除了 16 本书目录（各书独立仓库），导致 `grep`/`ripgrep` 会**静默跳过**这些书。全库检索必须用脚本（`audit_library.py`）或显式指定路径，**不要相信 grep 的"查无此项"**。
2. **不判内容**：情节逻辑、谜题公平性、人物弧光、爽点是否达标，脚本一律不判——仍靠 04 清单内容项与独立审核。
3. **换词复写抓不到**：C1/C3 基于内容字符 8-gram，同义改写式注水（换词不换意）无法识别，需人工抽检。
4. **幽灵条目是启发式**：人物档案"正文 0 命中"的候选需人工确认（可能是别名、称呼、尚未登场）。
5. **字数区间依赖宪法**：宪法未写明区间时用默认 2000–3000；建议各书在宪法参数区明确写出"单集 X–Y 字"。
